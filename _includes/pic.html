{% comment %} A photograph. The files live in /assets/img as .webp. assets/img/MANIFEST.json says what each one shows; _data/pics.yml carries their pixel sizes so every can set width and height and nothing on the page shifts while they load. EVERY IMAGE ON THIS SITE IS AI GENERATED. Wherever a photo appears at size the page carries a small mono label saying exactly that. If you add a photo slot, add the label with it - never quietly drop it. Params: src - the file stem, e.g. "wall-birthday-cake-sixtieth". No path, no extension. Falls back to a sensible default if left out. ratio - e.g. "4/5", "16/9", "1". Optional; sets aspect-ratio inline. The image covers the frame, so the same photo can fill any shape. class - extra classes on the frame. alt - real alt text for a photo that carries meaning. Leave it out for decorative tiles: the frame is then hidden from assistive tech and the surrounding element keeps its own aria-label. eager - true for the FIRST image on a page. It gets fetchpriority="high" and nothing else does - one LCP candidate per page, not nine. above - true for an image that sits INSIDE the first screenful but is not the LCP candidate, e.g. the other tiles of a hero collage. It does not lazy-load - a lazy image is skipped by the preload scanner and deferred past first layout, so an above-fold collage paints late - but it does not claim high priority either. Everything genuinely below the fold takes the default and lazy-loads. pos - object-position, e.g. "50% 30%", when the subject is not centred. sizes - override the responsive `sizes` hint for an unusual slot. The default, "(max-width:760px) 100vw, 1200px", is deliberately conservative: a phone takes the 640px copy, a desktop takes the full file exactly as before. thumb - true for a chip-sized slot - the moderation gate wall renders these at 34px, or 44px on /functions/. Serves the 96px copy from /assets/img/thumb/ instead of the full photo. Only the stems listed in the thumb folder have one; adding a new chip means adding a thumb for it. width and height stay the source values - the thumb is the same shape, so the aspect ratio hint is still right. {% endcomment %} {% assign src = include.src | default: 'wall-front-bar-high-table-flash' %} {% assign meta = site.data.pics[src] %} {% assign w = meta.w | default: 900 %} {% assign h = meta.h | default: 900 %} {% assign alt = include.alt | default: '' %} {% if include.thumb %}{% assign dir = 'thumb/' %}{% else %}{% assign dir = '' %}{% endif %} {% comment %} A 640px copy only exists where the source is wider than that - see assets/img/640.
